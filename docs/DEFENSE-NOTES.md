# Defense Notes — what changed, what we tuned, and the numbers that justify it

Companion to [`SUGGESTIONS.md`](../SUGGESTIONS.md) (which maps reviewer items
to outcomes). This document answers the *harder* defense questions: **what
exactly changed, which parameters were tuned and to what values, and what
evidence backs each choice.** Every number names its artifact.

---

## 1. The measurement discipline (say this first — it frames everything)

| Rule | Value | Why |
|---|---|---|
| Cross-validation | 5-fold StratifiedKFold, `seed=42`, shuffled | identical folds across every experiment → fold-paired deltas |
| Noise floor | **±0.0036 AUC** (observed fold std) | no gain below it is ever claimed; pre-registered in each script's docstring *before* results existed |
| Early stopping | inner 10% split of the **training folds only** | evaluation folds never influence training length (no leakage) |
| Tune/test splits for policies | 50/50, `seed=20260831` | thresholds, calibrators, percentile maps fit on TUNE, all reported numbers from TEST |
| Artifacts | regenerated by committed scripts only | every doc number traces to `reports/*.json`; nothing hand-edited |

**Soundbite:** *"One criterion decided every claim in this project, and it was
written down before any result existed."*

## 3. Hyperparameters — what we tuned, what we chose, and the proof

### 3.1 The sweep that licensed "defaults + early stopping"

`reports/tuning_cpu.json`: **14 configurations** over LightGBM/XGBoost
(learning_rate 0.01–0.03, num_leaves 31–127, min_child_samples 20–200,
subsample/colsample 0.7–0.9, reg_alpha 0–0.1, reg_lambda up to 10, up to 3000
trees). Best trial: **0.76802** vs baseline early-stopped 0.767 → gain
**+0.00102 — under a third of the noise floor.** Conclusion: on this data,
tuning beyond early-stopped defaults buys nothing claimable; effort was
redirected to features (which paid +0.0155).

### 3.2 The GBM protocol actually used everywhere

```
n_estimators = 2000 (ceiling, never reached)
learning_rate = 0.05
early stopping = 100 rounds on AUC, inner 10% stratified split of training folds
LightGBM num_leaves = 63 · XGBoost max_depth = 6, tree_method = hist
CatBoost od_type = Iter, od_wait = 100
seeds: fold seed 42; per-fold model seed = 42 + fold_index
```
Capacity is governed by early stopping, not by the tree budget — the
convergence study (`convergence.json`) shows a **fixed** 400-tree budget
*underfits* at large n (0.7581 vs 0.7607 early-stopped), which is why the
learning curve uses per-size early stopping.

### 3.3 Decision-layer parameters (these are POLICY, fitted on tune splits — never on test)

| Parameter | Value | How it was set | Source |
|---|---|---|---|
| Blend α (CBES weight) | **0.10** | measured cost table over α grid on the tune split; decisions use p_blend=(1−α)·p_ml + α·p_cbes | `blend_decision.json` |
| t_base (approve threshold) | **0.65** | cost-minimising threshold ("cost" method), replacing a degenerate fixed-range F1 sweep | `pipeline_summary` / `threshold_selection.py` |
| Approve / reject band | 0.6425 / 0.6575 | derived from t_base ± band; stamped per decision via threshold-artifact hash | decision engine + `/health` |
| Deferral rate | **22.5%** (band 20–25%) | underwriter-capacity requirement; threshold = tune-split quantile; gate condition 2's AUC-implied bound tension is *reported, not hidden* | `deferral_fix.json` |
| Deferral signal | −\|p_ml − t\| (Chow's rule) in serving; SGLB knowledge-uncertainty measured better in research (position 0.40 vs 0.14) but flipping it is a governance decision (ENGINE_VERSION bump) | `deferral_fix.json`, `uncertainty_deferral.json` |
| Exploration arm | 3% of auto-decides captured for review | counterfactual-labels design; never disabled | `relearning` docs |
| SGLB uncertainty model | 1000 iterations fixed (no early stop — SGLB's posterior interpretation requires a fixed budget), K=10 virtual ensembles | `uncertainty_deferral.json` |
| Monotone constraints | 21 features, signs from domain knowledge only (set fixed *before* training) | cost measured −0.0008 (inside noise), 0/14,400 violations | `monotone_catboost.json` |
| Cost matrix (studied) | FN:FP = 7.5:1 (LGD 0.75 vs margin 0.10) | class-weighted *training* refused: CI spans zero vs plain thresholding → economics stay in the decision layer | `cost_sensitive_catboost.json` |

### 3.4 Feature engineering v2 — the change that actually moved accuracy

319 columns from `application_train` + full `bureau.csv` (previously 9 coarse
aggregates). Families and their payoff (gain share of top-25, single
early-stopped LightGBM): `APP_EXT_MEAN` 30.3%, `APP_CREDIT_TO_ANNUITY` (term
proxy) 4.9%, bureau debt-to-credit ratios ~3%. Hygiene baked in: the
`DAYS_EMPLOYED == 365243` sentinel → NaN; thin files stay NaN + explicit
`BURO_has_bureau` flag (no imputing away missingness); only tables actually on
disk; serving 15-feature contract untouched.

## 4. Foundation-model settings (for "did you give them a fair shot?")

- **TabPFN-2.5:** pinned checkpoint; local context capped at 5,000 rows by
  8GB VRAM → Colab T4 serves **10,000-row context**; evaluated on 8,000
  id-joined rows with a row-alignment gate (join on SK_ID_CURR, 0 label
  mismatches, AUC reproduction) — the gate exists because an earlier
  uncommitted run mis-aligned rows, which is why *every* scored-row artifact
  now carries ids.
- **TabFM 1.0:** `[pytorch]` install, 5,000-row context, n_estimators=8,
  scored the *same* 8,000 ids as TabPFN for a paired comparison.
- **TabICLv2 (2026):** batch_size=2 + disk offload attempted; needs ~18GB
  scratch per fold at 24k context × 319 features — infeasible on an 8GB-GPU
  laptop; recorded as a deployability finding.
- **RealMLP-TD (2026):** benchmark-tuned defaults (the library's premise),
  median imputation fit per training fold (mandatory for a neural net, same
  as our LogReg arm — preprocessing, not tuning). Lost all 5 folds.

## 5. What changed since the September review (chronology)

1. **Provenance everywhere** — ENGINE_VERSION + artifact + threshold hash on
   every decision; hardcoded `/health` constants replaced by live artifact
   reads (the old ones had served synthetic-era numbers).
2. **Foundation models measured honestly** — TabPFN re-scored with id
   verification; TabFM added; both fusion-killed.
3. **Deferral inversion fixed** — root cause measured (0.307 calibration
   offset dominating |p_ml − p_cbes|); uncertainty routing wins at z=−99.7;
   opt-in via `SMARTLEND_DEFERRAL_MODE=uncertainty`.
4. **Feature engineering v2** — the accuracy lever: 0.7603 → 0.7757 under
   pre-registered rules; fusion re-denied on the improved models.
5. **Three model-modification studies** — uncertainty deferral (claim
   granted), monotone constraints (free), cost-sensitive training (null).
6. **2026 challenger screen** — RealMLP eliminated, TabICLv2 infeasible.
7. **Deployment** — Docker (886MB image), AWS (EC2+RDS+ECR via Terraform,
   IAM-role pulls, one-command apply/destroy), guest login for Firebase-free
   hosts, demo seeder incl. human-adjudicated rejections.

## 6. Questions we expect, answers we have

- **"Why not deploy TabPFN if it beats your serving model?"** Licence
  (non-commercial incl. outputs), 10GB GPU dependency, and the governance rule
  that advisory AI never writes `final_decision`. It serves as a second
  opinion; the connection run proves the remote model is genuine (remote AUC
  0.7100 on 400 held-out labelled rows).
- **"Did you tune enough?"** 14-trial sweep: best +0.001, under the noise
  floor (§3.1). The same +0.0036 rule that rejected our own tuning gains also
  rejected every fusion — the criterion is symmetric, which is what makes it
  credible.
- **"Why is the serving model a LogisticRegression at 0.6919 when research
  has 0.7757?"** Serving uses a 15-feature train/serve contract matching the
  live derivation path; the research track uses 319 offline features. Closing
  that gap is roadmap (promote the FE-v2 pipeline behind the same contract
  discipline), not an oversight — and the version stamping exists precisely so
  the two tracks can never be confused.
- **"Where does more accuracy come from next?"** Measured answer: data. The
  learning curve still rises at 246k (+0.010 per doubling), and the four
  unused Home Credit side tables are the known ~+0.015 path to ~0.79.
